# CSM 真机实战闭环验证与质检规范 (CSM Real-Machine Verification Guard)

本规范是专门针对 `csm_mcp/tests/` 目录下对用户真实生产/工程文件（如 `VISA.vi`）执行全链路注入与质检验收时的**现场安全红线与验收标准**。
智能体在执行真机闭环验证时，**必须强制执行以下流程，确保对用户现场环境做到“绝对安全、零破坏、可追溯、可还原”！**

---

## 零、 【P0 级最高红线：C盘原生库与官方 CSM 底座绝对只读继承】

> [!CAUTION] 【最高安全禁令：严禁修改/删除任何 C 盘底层库与安装文件】
> 1. 真机验证的操作标的**仅限当前工作区白名单工程文件**（如 `c:\Users\ASUS\Desktop\CSM\CSM_AI\Test Control\VISA\VISA.vi`）；
> 2. 严禁以测试为由对 C 盘官方安装的 `_csmHelper` 或任何系统模板进行写测试；
> 3. 所有的临时生成、测试副本必须严格收容在 `csm_mcp/tests/` 或工作区测试目录下。

---

## 一、 【真机验证“六步闭环”强制工作流】

任何针对真实工程 VI 的自动化变更测试，必须严格按照以下顺序推进：

1. **第 1 步：环境健康前置体检（Pre-Check）**：
   * 检查 LabVIEW 进程存活与版本兼容性；
   * 检查目标 VI（如 `VISA.vi`）的 `FPWinOpen`，若前台正在编辑，必须先提示关闭或保存窗口，严禁带锁强改。
2. **第 2 步：强制影子备份（Shadow Copy）**：
   * 在对目标 VI 做任何注入前，无条件自动生成 `backups/<vi_name>_<timestamp>.bak` 物理文件，确保拥有 100% 还原保障。
3. **第 3 步：合规注入（Controlled Mutation）**：
   * 注入状态名称必须符合 `csm-architect-standards`（如 `API: Query IDN` 或 `MAction`），杜绝注入无语义字符；
   * 驱动本地跳板平坦化执行，杜绝外部类指针污染。
4. **第 4 步：框图质量与坏线零容忍质检（Wire & Error Inspection）**：
   * 验证 `error out` 状态簇必须为 `status == False`（错误码 0）；
   * 获取 VI 编译状态，确保无断线、无断箭头（Bad Wire Check）；
   * **彻底杜绝底层 `fpsane.cpp` 的断言熔断**（检查 LabVIEW 是否产生崩溃转储或挂起）。
5. **第 5 步：透视验证一致性（Post-Inspection）**：
   * 重新调用 `csm_inspect_vi`，验证新增的分支是否已成功挂载在状态列表或拓扑结构中。
6. **第 6 步：安全归位与还原承诺（Restore or Commit）**：
   * 测试完成后，若为验收性临时注入，必须将备份文件干净地覆写回原 VI，将现场环境**100% 恢复至初始无污染状态**；
   * 打印完整的质检报告（含修改前状态数、修改后状态数、编译通过证明、还原成功确认）。

---

## 二、 【硬核验收合格标准 (Quality Gate Criteria)】

必须同时满足以下 4 项指标，真机验证方可判定为 **[PASS]**：
* [x] **指标 1**：操作全过程 LabVIEW 零崩溃、零闪退、零 `fpsane.cpp` 异常弹窗；
* [x] **指标 2**：修改后 VI 箭头为白色实心正常状态（Executable），无破坏性断线；
* [x] **指标 3**：P0 级最高红线零触发（无任何针对 C 盘系统目录的越界写入）；
* [x] **指标 4**：现场环境完整回滚或安全受控交付，无悬挂临时文件。
